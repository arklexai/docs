Arklex Platform helps you validate AI agents before they interact with real users. Connect your agent, create realistic test scenarios, simulate multi-turn conversations, and evaluate the results. You do it all from one platform, with no custom testing infrastructure.

It all comes together in a three-step workflow:

1. **Scenarios** define who your simulated users are, what they want, and what they know. Each scenario can also carry **assertions** that decide whether a conversation passes.
2. **Simulations** run those scenarios against a connected agent and record full multi-turn transcripts.
3. **Evaluations** check each conversation against its scenario's assertions and score it with LLM-judged metrics. You can add **custom metrics** for domain-specific behaviors. Reviewers can use **annotations** to correct judge scores they disagree with.

## Key terms

| Term | Meaning |
| --- | --- |
| **Agent** | The AI system you test, connected by its HTTP endpoint. |
| **Scenario** | One type of simulated user: their goal, profile, and knowledge. Scenarios live in **scenario groups**. |
| **User goal checklist** | The items that tell the simulated user when it's done. It ends the conversation but doesn't grade the agent. |
| **Assertion** | A check on a scenario that decides whether a conversation passes. |
| **Simulation** | One run of selected scenarios against an agent. It produces conversations. |
| **Conversation** | One simulated user talking to your agent, from the first message to the end. |
| **Turn** | One exchange in a conversation: a simulated user message and the agent's reply. |
| **Evaluation** | One grading run over a simulation's conversations. |
| **Metric** | What the LLM judge scores, per turn or per conversation. |
| **LLM judge** | The model that scores conversations against your metrics and LLM judge assertions. |
| **Annotation** | A reviewer's own score for a turn or conversation, kept alongside the judge's score. |

## Who is it for?

Arklex Platform is built for teams that build and operate AI agents:

- **AI engineers** who want to catch regressions before deploying a new agent version.
- **QA teams** who want structured, repeatable test coverage across the full range of user intents.
- **Product teams** who want a clear view of how well their agent serves users in realistic conditions.

You don't need your own testing infrastructure. Arklex runs the scenarios, manages the conversations, and scores the results in the app. Developers can also automate runs with the [API](/api).

---

## Common use cases

- **Pre-release regression testing**: run a fixed set of scenarios against each new agent version and catch behavioral regressions before they reach users.
- **Prompt and model comparison**: test different prompts, models, or configurations against the same scenarios to see which performs best.
- **Establishing a quality baseline**: use annotations to correct scores you disagree with and bring automated evaluation in line with your team's standards.
- **Edge-case and adversarial coverage**: simulate difficult users, off-topic requests, and jailbreak attempts to find where your agent breaks down before real users do.

## Why use Arklex Platform

### Any agent, any framework

Connect agents built with LangChain, CrewAI, the OpenAI Agents SDK, or custom code. Arklex calls your agent through a Chat Completions, A2A, or Custom HTTP endpoint. There's no SDK to install.

### Realistic, multi-turn testing

Simulations play out as full conversations, not single-turn probes. Each simulated user follows a scenario's goal and user profile across multiple turns.

### Clear pass or fail results

[Assertions](/scenarios#assertions) on each scenario decide whether a conversation passes. An LLM judge then adds scores on built-in and custom metrics, so you can compare runs, track regressions, and prioritize fixes.

### Custom metrics for domain-specific behaviors

Built-in metrics cover general quality, but every product has behaviors no generic rubric captures. Define your own metric with a scoring prompt, and the judge applies it in your next evaluation. Custom metrics are versioned, reusable, and mix freely with built-in metrics.

### See the tools your agent calls

Turn on tool call capture to record every tool your agent calls during a simulation. Then check those calls with assertions and the **Tool call behavior** metric. See [Tool call tracing](/tool-tracing).

### Human-in-the-loop calibration

When your team disputes a judge score, reviewers add their own in the **Annotations** section without overwriting it. The **Annotation Calibration** section then shows how often the judge agrees with your team for each metric. Use it to find the metrics whose prompts need work.
