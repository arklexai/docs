## Getting started

<AccordionGroup>
  <Accordion title="How long does it take to run my first simulation?">
    If your agent has a public endpoint, you connect it and build scenarios in the app without writing code. A simulation with 10 scenarios, 1 conversation each, and 5 turns typically finishes in a few minutes. The [Quickstart](/quickstart) walks you through each step.
  </Accordion>

  <Accordion title="Does Arklex require changes to my agent code?">
    No. Arklex calls your agent over HTTP, so any endpoint Arklex can reach works without code changes. On cloud, the endpoint must be public. The one exception is tool call capture, which needs your agent to export OpenTelemetry traces. See [Tool call tracing](/tool-tracing).
  </Accordion>

  <Accordion title="What agent types does Arklex support?">
    Arklex supports three API types: **Chat Completions** (endpoints that follow the `/chat/completions` schema), **Agent to Agent (A2A)**, and **Custom HTTP** (any endpoint that takes and returns JSON). Agents built on LangChain, CrewAI, the OpenAI Agents SDK, or custom code connect through one of these without code changes.
  </Accordion>
</AccordionGroup>

## Simulations and evaluations

<AccordionGroup>
  <Accordion title="What's the difference between a simulation and an evaluation?">
    A **simulation** is the execution layer: it runs scenarios against your agent and produces conversation transcripts. An **evaluation** is the grading layer: it takes one completed simulation, checks each conversation against its scenario's assertions, and scores it with an LLM judge.
  </Accordion>

  <Accordion title="Are simulations single-turn or multi-turn?">
    Multi-turn. Each simulated user follows a scenario's goal and user profile across a full conversation. The transcripts reflect realistic interaction patterns rather than one-shot prompts.
  </Accordion>

  <Accordion title="How is this different from testing my agent manually?">
    Manual testing is slow, subjective, and hard to repeat. Arklex runs the same scenarios consistently across every agent version, grades them with defined assertions and metrics, and keeps a record you can compare over time. You catch regressions instead of rediscovering them in production.
  </Accordion>
</AccordionGroup>

## Metrics

<AccordionGroup>
  <Accordion title="What metrics does Arklex measure?">
    Built-in metrics cover general agent quality, such as helpfulness, coherence, and faithfulness, plus behavioral failures and tool use. Other built-in metrics score the simulated user. You can also define **custom metrics** for behaviors specific to your domain. See [Metrics](/metrics).
  </Accordion>

  <Accordion title="How do custom metrics work?">
    Write a scoring prompt that describes what good and bad look like. A custom metric returns a score on a 1 to 5 or 0 to 1 scale, or one of the labels you define. The LLM judge applies it in your next evaluation. Custom metrics are versioned, reusable across evaluations, and mix freely with built-in metrics.
  </Accordion>

  <Accordion title="Can I trust the LLM judge's scores?">
    The judge is a starting point, not the final word. When your team disagrees with a score, reviewers add their own on the **Annotations** tab. The **Annotation Calibration** tab then shows how often the judge agrees with your team for each metric. Use it to find the metrics whose prompts need work.
  </Accordion>
</AccordionGroup>

## Team workflow and security

<AccordionGroup>
  <Accordion title="Can multiple team members annotate the same evaluation?">
    Yes. Each reviewer scores independently. Owners see every reviewer's scores and the majority value next to the judge's score. Members see only their own scores until a row is resolved.
  </Accordion>

  <Accordion title="How are API keys and headers stored?">
    Agent header values and MCP auth headers, which typically hold API keys and auth tokens, are encrypted at rest. The app shows masked values, and the API returns only header names. Neither returns the raw secret after it's saved. Only header values are encrypted, so keep secrets out of request bodies.
  </Accordion>
</AccordionGroup>
